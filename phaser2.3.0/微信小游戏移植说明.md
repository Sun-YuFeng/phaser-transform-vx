# PlaySmart 微信小游戏移植说明

本文档记录将 **PlaySmart**（QiCi Engine + Phaser 2.3.0 / Pixi.js 2.2.8）从 Web Playable 移植到**微信小游戏**的完整改造过程，便于后续维护、重新构建与排查问题。

---

## 1. 项目概览

| 项 | 说明 |
|---|---|
| 引擎 | QiCi（qc-core）+ Phaser 2.3.0 + Pixi.js 2.2.8 |
| 游戏 | PlaySmart v2.7.0 |
| 运行环境 | 微信小游戏（`compileType: "game"`） |
| 入口 | `game.js` → `js/main.js`（构建产物） |
| 资源 | `resource/` 目录（由导出脚本从 `data.js` 解出） |

**核心思路**：不直接手改 `js/main.js`，而是维护 `js/replace_js/` 源文件 + `scripts/build-game-bundle.js` 补丁，构建时自动生成微信可用的单文件 bundle。

## 3. 构建流程

### 3.1 首次 / 资源变更后

```bash
# 1. 从 data.js 导出 resource/（需要完整 data.js 含 base64）
node scripts/export-assets-from-data.js

# 2. 修复 prefab / start 等 .bin 格式（见第 5 节）
node scripts/fix-prefab-bins.js
node scripts/fix-all-bin-json.js   # 图集类双重转义时按需运行

# 3. 生成 js/main.js
node scripts/build-game-bundle.js
```

### 3.2 仅改补丁或 replace_js 后

```bash
node scripts/build-game-bundle.js
```

### 3.3 微信开发者工具

1. 打开本项目（`compileType: "game"`）
2. **清缓存** → **重新编译**（改 `main.js` 或 `resource/` 后务必执行）
3. 确认 `project.config.json` 中 `packOptions.ignore` **未忽略** `js/main.js`

## 4. 入口文件 `game.js`

| 改动 | 目的 |
|---|---|
| `import './js/libs/weapp-adapter.js'` | 提供 `window`、`document`、`canvas` 等浏览器 API |
| `window.__wx = true` | 供引擎内各补丁识别微信环境 |
| `window.canvas = GameGlobal.canvas` | 绑定微信主 Canvas |
| `import './js/main.js'` | 加载构建后的单文件 bundle |
| `document.dispatchEvent({ type: 'load' })` | PlaySmart 依赖 `window load` 触发 `qici.init` |
| `waitGameStart()` 轮询 | 兜底：场景 `hasReady` 后自动 `gameStart()` + `checkLaunch()`，解决黑屏 |

## 5. 资源（`resource/`）修复

### 5.1 `.bin` 文件格式

QiCi 非音频资源在导出后应为 **JSON 数组**：

```json
["{\"uuid\":\"...\",\"type\":2,\"source\":[\".prefab\"]}", "{...prefab json...}"]
```

| type | 含义 |
|---|---|
| 1 | 场景（`.state`） |
| 2 | 预制体（`.prefab`） |

常见问题与脚本：

| 问题 | 现象 | 处理脚本 |
|---|---|---|
| 双重转义 `\\\\` | `JSON.parse` 失败 | `scripts/fix-all-bin-json.js` |
| 字面量 `\n` 未转真实换行 | `Expected property name at position 1` | `scripts/fix-prefab-bins.js` |
| 单对象 `{class,data}` 未包数组 | `Unexpected token` / 解析类型错误 | `scripts/fix-prefab-bins.js` |
| `start.bin` 格式错误 | `start开始界面不存在` | 同上（已含 start） |

已修复文件示例：`start/start.bin`、`ending/ending.bin`、`prefab/*.bin`、`scene/gamePlay.bin` 等。

### 5.2 资源加载方式

- `hasBase64()` 在构建中被强制返回 `false`，改为从 `resource/` 磁盘加载
- `js/replace_js/data.js` 现为 stub；完整重导出需恢复原始 `data.js`

### 5.3 音频

`resource/game/audio/*.mp3.bin` 为原始 ID3/MP3 二进制，走引擎 `isSound` 路径，与 JSON 文本型 `.bin` 不同。

## 6. 构建补丁详解（`scripts/build-game-bundle.js`）

构建时将 15 个源文件合并为 `js/main.js`，并应用以下补丁。

### 6.1 Phaser（`patchPhaser`）

| 补丁 | 说明 |
|---|---|
| `setUpRenderer` | 微信下使用 `window.canvas` / `GameGlobal.canvas`，跳过 DOM style 异常 |
| `addToDOM` / `removeFromDOM` | 微信下直接 return，不操作 DOM |
| `preUpdate` | 避免重复 `clearCurrentState` 导致状态切换异常 |
| `xhrLoad` | 用 `wx.getFileSystemManager().readFile()` 替代 `wx.request` |
| `fileComplete` | 兼容微信 `readFile` 返回的 data 格式 |
| `window.__wx && getSharedCanvas` | 简化为 `window.__wx`，统一走本地文件读取 |

### 6.2 QiCi 核心（`patchQcCore`）

| 补丁 | 说明 |
|---|---|
| `D.qc_game` / `window.qc_game` | 全局可访问，避免 `qc_game` 为 null |
| Stage/Camera/World/Input | 幂等初始化，避免重复构造 |
| `pt.Node` game 回退 | 使用 `D.qc_game` 作为 fallback |
| 资源 unpack | 第二段为 `{`/`[` 时按 UTF-8 JSON 解析，兼容文本型 scene/prefab |
| `findClass` | 增加 `qc._userScripts` 与短类名回退 |
| `Dom.appendChild` | `frontDomRoot`/`backDomRoot` 为 null 时跳过（微信无 DOM 根） |

### 6.3 加载配置（`patchQcLoading`）

| 补丁 | 说明 |
|---|---|
| `useLanguages: true` | 启用多语言 |
| 注释 `gameDiv` display / `postMessage` | 微信无 iframe 父页面 |
| `canvas: window.canvas` | 使用微信 Canvas 而非 `parent: 'gameDiv'` |
| `renderer: Phaser.WEBGL` | 强制 WebGL |

### 6.4 游戏脚本（`patchGameScripts`）

| 补丁 | 说明 |
|---|---|
| `_typeof` 重命名 | 避免多文件合并后严格模式冲突 |
| `hasBase64()` → `false` | 使用 `resource/` 文件 |
| 注入 `window.gameStart` | 原 bundle 缺少该函数，补全 playable 启动逻辑 |
| `ps` 挂到 `window` / `GameGlobal` | 解决 ES 模块作用域下 `window.ps` 未定义 |
| `AUTO_GAMESTART \|\| window.__wx` | 微信自动调用 `gameStart()` |
| **调整启动顺序** | 先 `hasReady=true`，再 `gameStart()`，再 `checkReady()` |
| `checkLaunch` 微信兜底 | 无 `hasStart` 时自动置 true |
| `onLoaded` | 微信下**不**执行 `UIRoot.visible=false` |
| `checkLaunch` → `s()` | 微信跳过开始面板阻塞，直接 `mainState.start()` |
| `DraggableItem` 双注册 | 同时注册 `"DraggableItem"` 与 `"ps.DraggableItem"` |

### 6.5 其他

| 文件 | 补丁 |
|---|---|
| `pl-adapter.js` | 去掉 `with` 语句（严格模式不兼容） |
| `languagesMgr.js` | 从 `qc_game.phaser.cache` 读语言包（旧版兜底） |
| bundle 尾部 | 导出 `assetsPackage`、`Phaser`、`ps`、`qc` 到 `GameGlobal` |

## 7. 启动流程（微信）

```
game.js
  → weapp-adapter + __wx + canvas
  → import js/main.js（bundle 执行）
  → document dispatch 'load'
  → qici.init → qici.loadGame
  → Phaser WebGL 渲染到 window.canvas
  → 加载 resource/scene/gamePlay
  → ps.onLoaded
       ├─ 非微信：UIRoot.visible = false
       └─ 微信：跳过隐藏
  → i()：hasReady=true → gameStart() → checkReady()
  → checkLaunch()：hasReady && hasStart → UIRoot.visible=true → gameLaunch
  → mainInit / gameReady → 可交互
```

**黑屏根因（已修复）**：`UIRoot.visible` 仅在 `gameLaunch` 时置 `true`，而 `gameLaunch` 需要 `gameStart()` 设置 `hasStart`；导出配置 `AUTO_GAMESTART: false` 且微信无 playable 点击层，导致永远黑屏。

## 8. 问题排查对照表

| 控制台现象 | 原因 | 处理 |
|---|---|---|
| `createElementNS` / strict 报错 | 多文件 strict 或 DOM API 缺失 | 单文件 bundle + `disableUseStrict` |
| `xhr request() not implemented` | 应用 `wx.request` 读本地资源 | `patchPhaser` readFile |
| `appendChild of null` | 微信 `frontDomRoot` 为 null | `patchQcCore` Dom 补丁 |
| `Class:ps.DraggableItem not exists` | 注册名与引用名不一致 | 双注册 + `findClass` 回退 |
| `gamePlay.bin` / `start.bin` Parse fail | `.bin` JSON 格式或转义错误 | `fix-prefab-bins.js` 等 |
| `window.gameStart is not a function` | bundle 截断缺少尾部 | `patchGameScripts` 注入 |
| 有 `gameReady` 无 `gameLaunch`、黑屏 | 未 `gameStart` / `UIRoot` 仍隐藏 | `game.js` waitGameStart + 启动顺序补丁 |
| `gameConfig == undefined` | 编辑器字段为空，可忽略 | 使用内嵌 `GAME_CFG` |
| `没配置拖拽目标` | `ItemView` 两次 `onInit` 的 info 日志 | 正常，不影响玩法 |
| `onHide/onShow not implemented` | Phaser 可见性 API 差异 | 非致命警告 |

## 9. 微信工程配置要点

`project.config.json`：

- `"compileType": "game"`
- `"disableUseStrict": true` — 与单文件 bundle 配合，减少 legacy 脚本报错
- `packOptions.ignore` 忽略 `js/replace_js`、`scripts`、`__canRun`，**不要忽略** `js/main.js`
- `babelSetting.ignore` 包含 `js/replace_js`，避免对源目录二次编译

---

## 10. 已知限制与后续可选优化

1. **资源完整性**：当前 `data.js` 为 stub，部分原始资源可能未导出；完整包需恢复原始 `data.js` 后重跑 `export-assets-from-data.js`
2. **背景音乐**：`game.js` 中 `audio/bg.mp4` 与引擎 BGM 路径并存，可按需统一
3. **开始/结束面板**：微信已强制跳过开始面板；若需展示 start UI，可改 `HAS_START_PANEL` 相关逻辑
4. **音频 `.mp3.bin`**：若无声，需单独验证 QC 二进制与 `wx.createInnerAudioContext` 路径
5. **`__canRun/`**：仅作参考，不是 PlaySmart 构建输入
